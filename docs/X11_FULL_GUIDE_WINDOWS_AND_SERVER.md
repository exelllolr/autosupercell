# Полная инструкция: X11 на Windows и на сервере

Пошаговая настройка проброса графики с Linux-сервера на твой ноутбук с Windows.

---

## Схема

```
[Сервер Linux]  ----SSH с X11---->  [Твой ноутбук Windows]
     xclock, Firefox, Chrome              VcXsrv показывает окна
```

- **На сервере:** ставим X11-библиотеки и программы (xclock, браузер и т.д.). Они рисуют в «виртуальный экран».
- **На ноуте:** ставим VcXsrv — это X-сервер, который принимает картинку по SSH и показывает окна в Windows.
- **Подключение:** `ssh -Y root@IP_СЕРВЕРА` — SSH пробрасывает этот «экран» с сервера на ноут.

---

# Часть 1. Windows (ноутбук)

## Шаг 1.1 — Скачать и установить VcXsrv

1. Открой в браузере: **https://sourceforge.net/projects/vcxsrv/**
2. Нажми **Download** или перейди в **Files** и скачай последний установщик (например `VcXsrv-64.1.20.14.0-installer.exe` или просто "Download" на главной).
3. Запусти скачанный `.exe`.
4. Установка: Next → Next → при необходимости «Install for all users» или «Just me» → Install → Finish.

Установщик нужен именно с SourceForge. Папка с исходниками (`vcxsrv-master`) для быстрого запуска не подходит — только для сборки.

---

## Шаг 1.2 — Запустить X-сервер (XLaunch)

1. Открой **Пуск** → найди **XLaunch** (или **VcXsrv XLaunch**) → запусти.
2. Пройди шаги мастера:

   | Окно | Выбор | Действие |
   |------|--------|----------|
   | **Step 1** | **Multiple windows** | Next |
   | **Step 2** | **Start no client** | Next |
   | **Step 3** | Включи **Disable access control** | Обязательно, иначе сервер отклонит подключение с SSH. Next |
   | **Step 4** | Finish | Готово |

3. В трее (возле часов) появится иконка X. Окно может быть свёрнуто — сервер уже слушает и ждёт клиентов.

Оставь XLaunch запущенным на всё время, пока хочешь смотреть окна с сервера.

---

## Шаг 1.3 — Переменная DISPLAY (в том терминале, откуда будешь делать SSH)

В **PowerShell** (или CMD), из которого будешь подключаться к серверу, выполни один раз в этой сессии:

```powershell
$env:DISPLAY = "localhost:0"
```

Проверка (опционально):

```powershell
echo $env:DISPLAY
```

Должно вывести: `localhost:0`.

Важно: делай это **в том же окне** PowerShell, откуда потом запустишь `ssh -Y`. В новом окне PowerShell переменную нужно задать снова (или добавь в профиль PowerShell, чтобы не вводить каждый раз).

---

## Шаг 1.4 — (Опционально) Брандмауэр Windows

Если позже при `ssh -Y` окна с сервера не появятся, но SSH подключается — возможно брандмауэр режет VcXsrv.

1. **Панель управления** → **Система и безопасность** → **Брандмауэр Защитника Windows** → **Разрешить приложение через брандмауэр**.
2. Найди **VcXsrv** (или **XLaunch**) и отметь галочки для **Частная** и **Публичная** сеть.
3. Если пункта нет — **Разрешить другое приложение** → Обзор → укажи `C:\Program Files\VcXsrv\vcxsrv.exe` (или где установился VcXsrv) → Добавить.

Сначала можно пропустить и проверить без этого; вернуться к брандмауэру только если окна не появятся.

# Часть 2. Сервер (Linux)

Подключайся к серверу **обычным SSH** (без X11 пока, просто чтобы выполнить команды):

```powershell
ssh root@130.12.44.191
```





- `xorg` — база X11.
- `x11-xserver-utils`, `x11-utils` — утилиты.
- `x11-apps` — тестовые программы с окнами: xclock, xeyes, xcalc, xterm и др.

---

## Проверка, что пакеты стоят

```bash
which xclock
```

Должен вывести путь, например `/usr/bin/xclock`. Если команда не найдена — перепроверь установку пакета `x11-apps`.

---

## Шаг 2.3 — (Опционально) SSH-сервер и X11 на сервере

На большинстве Ubuntu/Debian X11 forwarding уже включён в SSH. Проверить можно так:

```bash
grep -E "X11Forwarding|X11UseLocalhost" /etc/ssh/sshd_config
```

Ожидается что-то вроде:

- `X11Forwarding yes`
- `X11UseLocalhost no` или строка закомментирована — нормально.

Если `X11Forwarding no` — поменяй на `yes` и перезапусти SSH:

```bash
sudo sed -i 's/#X11Forwarding no/X11Forwarding yes/' /etc/ssh/sshd_config
sudo sed -i 's/X11Forwarding no/X11Forwarding yes/' /etc/ssh/sshd_config
sudo systemctl restart sshd
# или
sudo systemctl restart ssh
```

Дальше можно выйти с сервера (`exit`) и перейти к проверке с ноутбука.

# Часть 3. Подключение и проверка (ноутбук → сервер)

Делается **с твоего ноутбука (Windows)**.

## Шаг 3.1 — Убедиться, что VcXsrv запущен

XLaunch должен быть запущен (иконка X в трее), в том же терминале задана переменная:

```powershell
$env:DISPLAY = "localhost:0"
```

## Шаг 3.2 — Подключиться с пробросом X11

В **том же** окне PowerShell:

```powershell
ssh -Y root@130.12.44.191
```

Подставь свой IP и пользователя (например `root` или `ubuntu`). Флаг **`-Y`** включает доверенный (trusted) X11 forwarding — окна с сервера будут показываться на ноуте.

## Шаг 3.3 — Запустить тест на сервере

После входа на сервер выполни:

```bash
xclock
```

Окно с часами должно появиться **на экране твоего ноутбука**. Если да — X11 настроен правильно.

Другие тесты (из того же пакета `x11-apps`):

```bash
xeyes    # глаза за курсором
xcalc    # калькулятор
xterm    # терминал в окне
```

Закрыть окно — как обычно (крестик или закрыть процесс в терминале Ctrl+C, если запускал в foreground).

# Часть 4. Браузер и приложение

## 4.1 — Обычный браузер (Firefox/Chromium) на сервере

На сервере (уже по `ssh -Y root@...`):

```bash
sudo apt install -y firefox-esr
firefox
```

или:

```bash
sudo apt install -y chromium-browser
chromium
```

Окно браузера откроется на твоём ноуте. Возможны задержки из‑за передачи по сети — это нормально.

## 4.2 — Браузер из приложения (SuperCell / autosupercell)

Чтобы видеть окно Chrome, который запускает твоё приложение (Playwright/Patchright):

1. Подключайся только с пробросом X11: `ssh -Y root@130.12.44.191`.
2. На сервере в проекте в `.env` поставь: **`BROWSER_HEADLESS=false`**.
3. Запусти приложение в этой же SSH-сессии (Docker или uvicorn и т.п.).

Окно браузера приложения будет отображаться на ноутбуке, пока открыта эта сессия с `-Y`.

# Часть 5. Частые проблемы

| Проблема | Что проверить |
|----------|----------------|
| Окно не появляется на ноуте | 1) XLaunch запущен и в Step 3 была галочка «Disable access control». 2) В PowerShell перед `ssh` выполнено: `$env:DISPLAY = "localhost:0"`. 3) Подключаешься именно так: `ssh -Y root@IP`. |
| «cannot open display» на сервере | На ноуте не задан DISPLAY или не использован `-Y`. Задай `$env:DISPLAY = "localhost:0"` и заново зайди по `ssh -Y`. |
| «Connection refused» / «Network error» | Брандмауэр Windows блокирует VcXsrv — разреши приложение в брандмауэре (см. шаг 1.4). |
| Очень медленно / лагает | X11 гонит картинку по сети — для браузера это ожидаемо. Для отладки достаточно; для постоянной работы часто используют headless на сервере. |

# Краткий чеклист

**На ноутбуке (Windows):**  
1. Установить VcXsrv с SourceForge.  
2. Запустить XLaunch: Multiple windows → Start no client → **Disable access control** → Finish.  
3. В PowerShell: `$env:DISPLAY = "localhost:0"` затем `ssh -Y root@IP_СЕРВЕРА`.

**На сервере:**  
4. `sudo apt install -y xorg x11-xserver-utils x11-utils x11-apps`.  
5. После входа по `ssh -Y`: запустить `xclock` — окно должно быть на ноуте.

Если что-то не сработает — пришли вывод команды и на каком шаге остановился (Windows/сервер).
